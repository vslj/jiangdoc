> 目标：
> **让 50%～70% 的低级错误在“写代码之前”就消失**

---

# 一、先给你一个「编码前」的总心智模型

**编码前不是“想一想”那么虚，它有固定产出物：**

```
需求 → 数据 → 状态 → 边界 → 约束
```

你每写一个功能，至少要在脑子里（或纸上）走完这 5 步。

---

# 二、第一步：把「需求」翻译成“可判定结果”

### ❌ 错误方式（非常常见）

> “做一个登录页”
> “做一个列表”
> “做一个筛选功能”

这些 **没法判断对错**。

---

### ✅ 正确方式：写「判定条件」

你要在编码前就能回答：

* 什么情况下算成功？
* 什么情况下算失败？
* 失败时用户看到什么？

**示例：登录功能**

```text
成功：
- 输入合法账号密码
- 请求成功
- 存 token
- 跳转首页

失败：
- 账号密码错误 → 明确提示
- 网络失败 → 通用错误
- 多次点击 → 只发一次请求
```

> 🔑 **一条判定 = 一条未来的测试用例**

---

# 三、第二步：先设计「数据形状」，而不是组件

这是**防低级错误的第一大利器**。

### 你要先问的 4 个问题

1. 这个功能依赖哪些接口？
2. 每个接口**完整返回结构**是什么？
3. 哪些字段可能为空？
4. 哪些字段是 UI 派生的？

---

### 推荐你强制写这 3 个类型

```ts
// 1️⃣ 后端返回
interface LoginResponseDTO {
  token: string
  expireAt: number
  user?: {
    id: string
    name: string
  }
}

// 2️⃣ 前端内部使用
interface AuthState {
  token: string
  isLogin: boolean
  userName: string
}

// 3️⃣ 视图消费
interface HeaderViewModel {
  title: string
  showLogout: boolean
}
```

**经验铁律：**

> ❌ 组件不要直接吃 DTO
> ✅ DTO → State → ViewModel

你之前做 **医疗影像 / 复杂业务前端**，这一步尤其重要。

---

# 四、第三步：明确「状态边界」（很多 bug 死在这里）

### 在编码前你必须列清楚：

* 哪些是 **全局状态**（model / store）
* 哪些是 **页面状态**
* 哪些是 **临时状态**

---

### 示例（登录）

| 状态      | 放哪 | 原因          |
| ------- | -- | ----------- |
| token   | 全局 | 多处使用        |
| 用户信息    | 全局 | Header / 权限 |
| loading | 页面 | 生命周期短       |
| 错误信息    | 页面 | UI 专用       |

> 🔥 **状态放错地方 = 未来一定返工**

---

# 五、第四步：提前列出「边界条件清单」（防低级错误核心）

在写代码前，**你必须至少想 6 类边界**：

### ① 空值

* 接口返回 null？
* 数组为空？
* 字段缺失？

### ② 时序

* 连续点击？
* 快速切换路由？
* 上一个请求还没结束？

### ③ 权限

* 未登录访问？
* token 过期？
* 权限变更？

### ④ 异常

* 接口 500？
* 超时？
* JSON 解析失败？

### ⑤ 极端输入

* 空字符串
* 超长输入
* 特殊字符

### ⑥ 生命周期

* 组件卸载后 setState？
* effect 依赖是否完整？

**你可以直接照这个 checklist 过一遍。**

---

# 六、第五步：写“防错规则”，不是实现细节

在编码前，你要给自己下**不可违反的规则**。

### 示例

```text
- 不直接使用接口返回
- 所有 async 都 try/catch
- 所有可选字段必须有默认值
- loading 状态必须成对出现
- 任何副作用必须可取消
```

> 🔑 **规则 = 你未来少 debug 的原因**

---

# 七、把「编码前」变成一个可执行模板（送你）

你以后每写一个功能，可以用这个模板：

```text
【功能目标】
- 用户可以……

【成功条件】
- …

【失败条件】
- …

【接口 & 数据】
- 接口1：
- 返回字段：
- 可能为空：

【状态划分】
- 全局：
- 页面：
- 临时：

【边界清单】
- 空值：
- 异常：
- 并发：

【防错规则】
- …
```

**哪怕只花 5～10 分钟，也非常值。**
